# 数据流与联调计划

## 视觉部分

主机窗口和树莓派网页服务共用 `target_lock.py`。摄像头与推理负责生成 `Detection` 列表，选择逻辑只接收 ID、类别、检测框和置信度，不依赖模型实现。

```text
C922 → 图像镜像 → YOLO 检测 → ByteTrack 关联 → Detection 列表
                                            ↓
                                  鼠标点选 / TargetLock
                                            ↓
                             idle / tracking / lost + 偏差
```

- `idle`：没有用户选择，无位置输出。
- `tracking`：找到所选 ID 和类别，计算像素及归一化偏差。
- `lost`：所选 ID 不在当前帧、类别变化或框无效；保留选择，清空位置。

`centered` 只是归一化偏差均不超过死区的标志，不代表舵机已对准。

## 网页部分

相机线程持续采集并覆盖上一帧，推理线程取最新帧。推理结果、JPEG、帧编号和时间戳一起写入共享状态。HTTP 请求只短时间持有状态锁，不在锁内等待摄像头或运行模型。

预览响应头携带与 JPEG 同步读取的跟踪状态，浏览器据此绘制选中框。点击携带实际显示帧的编号和归一化坐标；服务端从该帧快照中选 ID，再用最新帧计算当前状态。

帧快照最多保留30份；3秒前的点击拒绝。预览超过3秒没有更新或推理线程出错，API 清空偏差。网页服务只监听回环地址，经 SSH 转发访问；控制请求还校验会话令牌。

当前 HTTP 服务用于局域网原型演示，不应直接绑定公网地址。它不是多用户控制系统；多个浏览器会共享同一个目标选择。

## 舵机部分

计划采用 Raspberry Pi + PCA9685 + 两轴 MG996R。以下内容尚未完成：

1. 核对实际舵机型号和位置型／连续旋转类型。
2. 验证独立稳压电源、线束、逻辑供电和共地连接。
3. 单轴校准中位、方向、可用行程，设置角度限位与速度限制。
4. 为控制循环增加位置时间戳、停止命令和失联处理。
5. 在低速、小角度下验证闭环跟随，再测试遮挡、目标丢失和恢复。

仓库暂不包含 PWM 输出或自动控制舵机的代码，不能作为完成云台闭环跟踪的证据。

## 验证范围

已完成 Windows GPU 与 C922 真实画面演示、人物／手机检测、点选锁定和慢速跟踪。一次约273秒的主机运行处理2691帧；该运行包含交互、推理、绘图和等待，不是模型 FPS 基准，也不是检测准确率测试。

树莓派安装曾因存储读写错误中断。CPU 依赖和导出脚本已修订，但 NCNN 导出、真实摄像头推理和网页完整链路仍需在稳定的树莓派系统上验证。没有经过验证的云台误差、响应时间或目标保持率指标。
