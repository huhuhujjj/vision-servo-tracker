# 开发计划

## 已完成的软件部分

- C922 主机端采集、YOLO26n 检测与 ByteTrack 编号。
- 人物和手机等已识别目标的点选、解除锁定、中心偏差和 LOST 状态。
- 共用目标选择模块，避免主机端和网页端采用不同的坐标约定。
- 按显示帧编号解释网页点击，拒绝过期点击，断线或读取超时后清空偏差。
- Windows / Linux 核心逻辑自动检查；推理依赖按运行平台选装。

## 下一步：树莓派端验收

前提是系统盘稳定读写，容量识别正常。当前原型的树莓派实机验收尚未完成。

1. 在64位 Raspberry Pi OS 安装 CPU 依赖并记录版本。
2. 导出416输入的 NCNN 模型，验证模型能够加载和推理。
3. 验证 C922 实时取帧、浏览器预览、鼠标点选、解除锁定及离线提示。
4. 分别记录416、640输入的处理速度、画面延迟和小目标漏检情况。

## 随后：舵机联调

先核对实际舵机型号、电源和接线，再进行单轴手动校准。确认中位、方向、限位和限速后，才将偏差接入控制循环。目标丢失、通信中断和程序退出时的停止行为需要单独验收。

## 结果记录方式

每次测试注明软件版本、硬件、输入尺寸、目标、场景和持续时间。记录重复次数与失败情况，不把单次演示的帧数写成准确率或性能基准。

尚未测量的指标包括检测准确率、遮挡后身份保持率、端到端延迟、云台跟随误差和停止响应时间。相关数据应在实验完成后补充。
